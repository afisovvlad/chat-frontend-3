🎣 Хук useHybridSearch
Гибридный поиск: локальная фильтрация + глобальный поиск через бэкенд с отображением результатов в отдельных секциях.

📋 Сигнатура

useHybridSearch<T>(
localData: T[],
localFilterFn: (items: T[], searchTerm: string) => T[],
globalSearchFn?: (searchTerm: string, signal?: AbortSignal) => Promise<T[]>,
debounceDelay?: number, // по умолчанию 300
globalPrefix?: string, // по умолчанию '@'
globalMinLength?: number // по умолчанию 3
): UseHybridSearchReturn<T>

🔧 Параметры

# localData: T[]

Исходный массив данных для локальной фильтрации.
Пример: кешированные контакты из RTK Query.

# localFilterFn: (items: T[], searchTerm: string) => T[]

Функция фильтрации локальных данных. Должна возвращать отфильтрованный массив.
Пример: filterContacts(contacts, 'айрат').

# globalSearchFn?: (searchTerm: string, signal?: AbortSignal) => Promise<T[]>

Асинхронная функция запроса к бэкенду. Поддерживает AbortSignal для отмены запросов.
Пример: обёртка над useLazySearchGlobalContactsQuery().unwrap().

# debounceDelay?: number (по умолчанию 300)

Задержка в миллисекундах перед выполнением глобального поиска. Снижает нагрузку при быстром вводе.

# globalPrefix?: string (по умолчанию '@')

Префикс, который активирует глобальный поиск.
Пример: ввод @айрат → поиск на бэке, ввод айрат → только локальная фильтрация.

# globalMinLength?: number (по умолчанию 3)

Минимальная длина запроса после удаления префикса для вызова API.
Зачем: экономия трафика, защита от лишних запросов при коротких вводах (@а, @).

📦 Возвращаемое значение

🔹 Состояние поиска
searchTerm (string) — Текущее значение поля поиска (сырой ввод пользователя)
isGlobal (boolean) — Активен ли глобальный режим (определяется по префиксу @)
isLoading (boolean) — Идёт ли загрузка глобальных результатов
error (Error | null) — Ошибка глобального запроса (если была)

🔹 Результаты (основное для секций)
sections (SearchSectionData<T>[]) — ✨ Основной массив для рендеринга: секции с заголовками и данными
totalResults (number) — Общее количество результатов во всех секциях

🔹 Результаты (для обратной совместимости)
globalResults (T[]) — Данные, полученные от бэкенд-API
localResults (T[]) — Локально отфильтрованные данные
results (T[]) — «Умный» объединённый массив: isGlobal ? globalResults : localResults

🔹 Обработчики
handleSearchChange ((value: string) => void) — Основной обработчик ввода (передавай в onChange поля поиска)
handleClear (() => void) — Полная очистка поиска и результатов
setGlobalResults (Dispatch<T[]>) — Прямое управление глобальными результатами (для моков/тестов)

🧩 Интерфейс SearchSectionData<T>

export interface SearchSectionData<T> {
title: string; // Заголовок секции
items: T[]; // Массив элементов для отображения
type: 'local' | 'global'; // Тип секции
isLoading?: boolean; // Состояние загрузки (для глобальных секций)
showHeader?: boolean; // ✨ Показывать ли заголовок секции (по умолчанию true)
}

# Поле showHeader

false
--Когда использовать: Заголовок уже рендерится в другом месте (например, в ContactsHeader)
--Пример: Локальные контакты
true (значение по умолчанию)
--Когда использовать: Нужно показать заголовок секции
--Пример: Глобальный поиск пользователей, группы, каналы

🎯 Быстрая памятка

Показываем секцию с заголовком?
│
├─ Это локальные контакты?
│ └─ Да → showHeader: false (заголовок в ContactsHeader)
│
├─ Это глобальный поиск / группы / каналы?
│ └─ Да → showHeader: true (нужен заголовок секции)
│
└─ Не уверены?
└─ Оставь по умолчанию (true) — заголовок просто покажется

🎯 Примеры использования
✅ Вариант 1: Рендеринг через секции (рекомендуемый)

const {
sections,
totalResults,
searchTerm,
handleSearchChange,
handleClear,
isLoading
} = useHybridSearch<ContactsSchema>(
localContacts,
filterContacts,
fetchGlobalContacts,
300,
'@',
3
);

return (
<>
<Search 
      value={searchTerm} 
      onChange={handleSearchChange} 
      onClear={handleClear} 
    />

    {/* Пустой результат */}
    {totalResults === 0 && searchTerm.trim().length > 0 && !isLoading && (
      <NotSearch />
    )}

    {/* Секции с результатами */}
    {sections.map((section, index) => (
      <SearchSection
        key={`${section.type}-${index}`}
        title={section.title}
        isLoading={section.isLoading}
        showHeader={section.showHeader ?? true} // ✨ Контроль заголовка
      >
        <ContactsListContent contacts={section.items} />
      </SearchSection>
    ))}

</>
);

✅ Вариант 2: Гибкий рендер (раздельные массивы)

const {
searchTerm,

return (

    {/* Локальные результаты (без заголовка — он в ContactsHeader) */}

      >

    {/* Загрузка */}

// Для случаев, когда не нужна секционная структура

return (
<>
<Search value={searchTerm} onChange={handleSearchChange} onClear={handleClear} />

    {results.length === 0 ? (

    ) : (
      <ContactsListContent contacts={results} />
    )}

</>
);

🔍 Визуальная схема работы

useHybridSearch(...)
│
├── 📊 Состояние
│ ├── searchTerm: string ← текущий ввод
│ ├── isGlobal: boolean ← режим: локальный/глобальный
│ ├── isLoading: boolean ← загрузка API
│ └── error: Error | null ← ошибка запроса
│
├── 📦 Результаты для секций (✨ новое)
│ ├── sections: SearchSectionData<T>[]
│ │ ├── [0]: { title: '', items: [...], type: 'local', showHeader: false }
│ │ └── [1]: { title: 'Пользователи А-Чата', items: [...], type: 'global', showHeader: true }
│ │
│ └── totalResults: number ← сумма всех items.length
│
├── 📦 Результаты (обратная совместимость)
│ ├── globalResults: T[] ← от API
│ ├── localResults: T[] ← локальная фильтрация
│ └── results: T[] ← computed: isGlobal ? global : local
│
├── ⚙️ Обработчики
│ ├── handleSearchChange: (value: string) => void
│ ├── handleClear: () => void
│ └── setGlobalResults: Dispatch<T[]>
│
└── 🔄 Логика формирования секций
├── Если ввод БЕЗ @ и есть локальные результаты:
│ └─→ Секция: showHeader: false (заголовок в ContactsHeader)
│
├── Если ввод С @ и есть глобальные результаты:
│ └─→ Секция: showHeader: true (заголовок "Пользователи А-Чата")
│
└── Если результатов нет → пустой массив sections

Практические советы
🎯 Когда использовать sections
✅ Тебе нужно показать результаты в отдельных контейнерах с заголовками
✅ Заголовки разных типов результатов должны отличаться
✅ Планируешь масштабировать: добавить секции для групп, каналов, чатов

🎯 Когда использовать results / localResults / globalResults
✅ Простой список без разделения на секции
✅ Кастомная логика объединения результатов

🎯 Как работает globalMinLength
Ввод: "@а" → длина после @ = 1 < 3 → ❌ запрос к API НЕ уходит
Ввод: "@ай" → длина после @ = 2 < 3 → ❌ запрос к API НЕ уходит  
Ввод: "@айр" → длина после @ = 3 ≥ 3 → ✅ запрос уходит после debounce

🎯 Контроль заголовков через showHeader

// Локальные контакты: заголовок уже в ContactsHeader
{
title: 'Контакты пользователей А-чата', // можно оставить пустым
showHeader: false // ✨ не рендерить заголовок в секции
}

// Глобальные пользователи: нужен заголовок секции
{
title: 'Пользователи А-Чата',
showHeader: true // ✨ рендерить заголовок
}

⚠️ Важные заметки
🔹 AbortController: хук автоматически отменяет предыдущие запросы при новом вводе — утечек памяти и race conditions не будет.
🔹 Дебаунс: глобальный поиск использует debounce — результаты появляются с задержкой debounceDelay. Локальная фильтрация работает мгновенно.
🔹 Инициализация: при пустом searchTerm хук заполняет localResults всеми localData — список не будет пустым при загрузке.
🔹 Префикс: globalPrefix проверяется через trim().startsWith() — пробелы до/после @ не сломают логику.
🔹 Типизация: дженерик <T> распространяется на все массивы — убедись, что localFilterFn и globalSearchFn работают с одним типом.
🔹 showHeader по умолчанию: если не передать showHeader, компонент SearchSection покажет заголовок (true по умолчанию).

🧪 Пример интеграции с RTK Query

// 1. Lazy-триггер для глобального поиска
const [triggerSearch] = useLazySearchGlobalContactsQuery();

// 2. Функция-обёртка для хука
const fetchGlobalContacts = useCallback(
async (term: string, signal?: AbortSignal): Promise<ContactsSchema[]> => {
try {
const payload: CheckContactRequest[] = [{ phone_or_nickname: term }];
const result = await triggerSearch(payload, { signal }).unwrap();
return sortContactsByStatus(result?.results ?? []);
} catch (error) {
console.error('Global search error:', error);
return [];
}
},
[triggerSearch]
);

// 3. Использование хука
const {
sections,
totalResults,
searchTerm,
isGlobal,
isLoading,
handleSearchChange,
handleClear
} = useHybridSearch<ContactsSchema>(
localContacts, // из кеша: cacheResponse?.results ?? []
filterContacts, // локальная фильтрация
fetchGlobalContacts, // запрос к API
300, // debounce
'@', // префикс
3 // globalMinLength
);

// 4. Рендеринг
return (

  <div>
    <ContactsSearch
      value={searchTerm}
      onChange={handleSearchChange}
      onClear={handleClear}
    />
    
    {sections.map((section, index) => (
      <SearchSection
        key={`${section.type}-${index}`}
        title={section.title}
        isLoading={section.isLoading}
        showHeader={section.showHeader}
      >
        <ContactsListContent contacts={section.items} />
      </SearchSection>
    ))}
  </div>
);
