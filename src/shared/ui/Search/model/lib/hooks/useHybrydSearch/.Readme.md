## Хук useHybridSearch возвращает два отдельных массива результатов + один "умный" объединённый для удобства.

📦 Что возвращается (массивы)

Поле | Тип | Описание | Когда использовать

globalResults | T[] | Результаты от бэкенд-API | Когда нужен полный поиск по базе

localResults | T[] | Локально отфильтрованные данные | Для мгновенного отклика, offline

results | T[] | Вычисленное: isGlobal ? globalResults : localResults | Для простого рендера без логики переключения

🎯 Пример: как использовать оба массива

const {
searchTerm,
globalResults, // 🔹 Массив 1: от API
localResults, // 🔹 Массив 2: локальный
results, // 🔹 "Умный" массив (auto-select)
isGlobal,
isLoading
} = useHybridSearch(chats, filterChats, api.searchChats);

// ─────────────────────────────────────────
// Вариант 1: Простой — используем results
// ─────────────────────────────────────────
return (
<List>
{results.map(chat => (
<ChatItem key={chat.id} chat={chat} />
))}
</List>
);

// ─────────────────────────────────────────
// Вариант 2: Гибкий — работаем с массивами раздельно
// ─────────────────────────────────────────
return (
<>
{/_ Показываем локальные результаты всегда _/}

<Section title="Последние чаты">
{localResults.slice(0, 5).map(chat => (
<ChatItem key={chat.id} chat={chat} />
))}
</Section>

    {/* Если глобальный поиск активен — показываем API-результаты отдельно */}
    {isGlobal && (
      <Section title="Найдено в базе">
        {isLoading ? (
          <Spinner />
        ) : globalResults.length > 0 ? (
          globalResults.map(chat => (
            <ChatItem key={chat.id} chat={chat} highlight />
          ))
        ) : (
          <Empty text="Ничего не найдено" />
        )}
      </Section>
    )}

</>
);

🔍 Визуальная схема возврата

useHybridSearch(...)
│
├── 📊 Состояние
│ ├── searchTerm: string
│ ├── isGlobal: boolean
│ ├── isLoading: boolean
│ └── error: Error | null
│
├── 📦 Результаты (три массива!)
│ ├── globalResults: T[] ← от API
│ ├── localResults: T[] ← локальная фильтрация
│ └── results: T[] ← computed: isGlobal ? global : local
│
├── ⚙️ Обработчики
│ ├── handleSearchChange: (value: string) => void
│ ├── handleClear: () => void
│ ├── handleClearLocal: () => void
│ └── handleClearGlobal: () => void
│
└── 🎛 Продвинутые (опционально)
├── setGlobalResults: Dispatch<T[]>
└── setLocalResults: Dispatch<T[]>

💡 Практический совет
Используйте results, если:
✅ Вам нужно просто отрендерить список
✅ Логика "глобальный приоритет" подходит
✅ Не нужна сложная UI-логика
Используйте globalResults / localResults раздельно, если:
✅ Хотите показать оба списка одновременно
✅ Нужна разная визуализация для глобальных/локальных
✅ Планируете кастомную логику объединения (например, merge без дублей)

// Пример: merge без дублей по ID
const merged = useMemo(() => {
const globalIds = new Set(globalResults.map(item => item.id));
const uniqueLocal = localResults.filter(item => !globalIds.has(item.id));
return [...globalResults, ...uniqueLocal];
}, [globalResults, localResults]);

## Хук возвращает два независимых массива: globalResults и localResults.

Плюс третий — results — для удобства, если не нужна кастомная логика.
