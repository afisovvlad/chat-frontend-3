## UserCardSkeleton — компонент‑заглушка для карточек пользователей

# Описание

UserCardSkeleton — универсальный компонент для отображения загрузочных скелетонов (заглушек) в интерфейсе, имитирующий внешний вид UserCard для разных типов сущностей:

# чаты (CHAT);

# контакты (CONTACT);

# чёрный список (BLACK_LIST);

# профиль (PROFILE).

Компонент позволяет:

рендерить несколько скелетонов за раз (через проп count);

адаптировать макет под разные типы карточек;

поддерживать единый стиль анимации загрузки.

# Установка

Компонент не требует внешних зависимостей. Подключите:
import { UserCardSkeleton } from '@/shared/ui/Skeleton';

# Использование

Примеры

# Один скелетон для чата

<UserCardSkeleton type={UserCardType.CHAT} />

# Пять скелетонов для контактов

<UserCardSkeleton type={UserCardType.CONTACT} count={5} />

# Три скелетона для чёрного списка

 <UserCardSkeleton type={UserCardType.BLACK_LIST} count={3} />
 
# Один скелетон для профиля

<UserCardSkeleton type={UserCardType.PROFILE} />

## Структура компонента

Каждый скелетон состоит из:

Аватар‑заглушка (cls.avatar) — круг 48×48 px.

Блок информации (cls.info) — основная область с подблоками.

Шапка (cls.header) — содержит:

имя‑заглушка (cls.nameSkeleton);

для чатов: статус и время (cls.statusSkeleton, cls.timeSkeleton).

Футер (cls.footer) — содержит:

для чатов: сообщение‑заглушка (cls.messageSkeleton);

для контактов/ЧС: статус онлайн‑заглушка (cls.onlineSkeleton);

для профиля: никнейм‑заглушка (cls.nicknameSkeleton).

Кнопка удаления (cls.trashBtnSkeleton) — только для BLACK_LIST.

## Стили

Стили определены в UserCardSkeleton.module.scss. Основные особенности:

Фон: var(--color-gray-100).

Заглушки: var(--color-gray-500).

Анимация: пульсирующий эффект skeleton-loading (1.5 с, бесконечно).

Адаптивность: гибкие отступы и размеры под каждый тип.

## Кастомизация

Чтобы изменить цвета или анимацию:

Откройте Skeleton.module.scss.

Измените переменные (например, --color-gray-100).

Обновите @keyframes skeleton-loading при необходимости.

# Рекомендации

Используйте count разумно

Для списков — count={5–10}.

Для одиночных карточек — count={1} (по умолчанию).

Синхронизируйте с реальными данными

Количество скелетонов (count) должно соответствовать ожидаемому числу элементов в списке.

Оптимизируйте производительность

Избегайте count > 20 без виртуализации списка.

Используйте memo (уже применён в компоненте).

Обеспечьте доступность

Добавьте aria-label к корневому элементу, если это требуется для скринридеров.

Зависимости
